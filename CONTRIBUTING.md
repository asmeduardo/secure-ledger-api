# Contribuição

Toda alteração deve começar por um problema e por critérios de aceite verificáveis. Código, testes, migrações e documentação pertencem à mesma entrega quando tratam a mesma mudança.

Antes do pull request:

1. execute os testes direcionados durante o desenvolvimento;
2. execute o gate completo uma vez ao final;
3. confirme que nenhum segredo ou dado pessoal foi incluído;
4. descreva os riscos e as evidências no pull request.
